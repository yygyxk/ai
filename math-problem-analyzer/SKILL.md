# 智能数学题型解析与拓展专家 (Math Problem Analyzer & Expander)

**版本**：v1.0
**最后迭代时间**：2026-05-22

---

## 技能描述
本技能专为教研备课与学生个性化辅导设计。当用户提供一道或多道数学题目（图片、文本、截图均可）时，本 Agent 将化身为“资深教研专家”，深度解构题目的考查逻辑、重难点与易错点，并跨越云端资料库（重点检索 `math-materials` 仓库）及全网寻找同类变式题。随后，系统会生成一份结构极简、排版纯净的专属题型解析 MD 文档。
**核心特色**：内置了“专家教师审查”和“格式质检”双重子 Agent 机制，确保输出内容的教学专业度和排版（特别是 LaTeX）的零瑕疵。

---

## 触发条件
当用户上传题目（图片或文字）并附加以下类似指令时触发：
- "帮我分析一下这道题"
- "找几道类似的题"
- "出一份这道题的同类拓展"
- "解构这道高考题"

---

## 执行工作流 (Agent Workflow)

### Step 1：🧠 原题智能解构 (Problem Analysis)
读取用户提供的题目，利用视觉或文本能力进行深度解构，提取以下核心教研信息：
- **考查知识点**：精确到三级知识点（如：非“导数”，而是“导数在研究极值中的应用-隐零点问题”）。
- **考查形式**：题型载体与设问方式（如：多选题、压轴大题的第一问等）。
- **题目类型**：概念辨析、计算求解、逻辑推断、综合应用创新等。
- **重难点**：破题的“题眼”或思维转折点。
- **易错点**：学生常踩的坑（如忽视定义域、漏掉空集讨论等）。

### Step 2：🔍 跨域海量搜题 (Retrieval & Expansion)
结合 Step 1 中提取的关键特征，启动搜题引擎：
1. **首选题源**：主动检索远端教辅仓库 `math-materials/资料` 与 `math-materials/真题` 目录中的内容。
2. **拓展题源**：利用全网搜索工具，寻找近年高考真题、名校模拟题中完全同源或变式的考题。
3. **筛选标准**：挑选 3~5 道题，必须遵循“难度递增”原则（基础变式 -> 综合变式 -> 拔高创新）。

### Step 3：📝 初稿生成 (Drafting Document)
根据分析和检索结果，严格按照以下骨架生成 Markdown 初稿。
> **⚠️ 严格极简命名规范**：所有的各级标题（包括#、##、###等）以及题目编号（如【原题】、【变式1】）旁边，**严禁加上任何括号标注来源、难度或宣传语**。保持极度干净。

**MD 文档骨架模板：**
```markdown
# [核心知识点名称] 题型深度解析与拓展

## 一、 命题密码解析
- **考查知识点**：...
- **考查形式**：...
- **高考占比与频次**：结合历年北京卷等大数据，简述该考点的分值占比与出题频率。
- **题目类型**：...

## 二、 破题核心与易错防雷
- **思维重难点**：...
- **易错防雷区**：...

## 三、 原题精准剖析
**【原题】**
（原题题目内容）
**【规范解答】**
（原题的详细解答过程，要求极致严谨的 LaTeX 排版）

## 四、 同类题型进阶拓展
**【变式 1】**
（题目内容）
**【解析】**
（详细解答）

**【变式 2】**
（题目内容）
**【解析】**
（详细解答）
（... 递增至 3-5 道题）
```

### Step 4：🧑‍🏫 专家教师子 Agent 审查 (Pedagogical Review)
初稿完成后，**绝不可直接落地或交付**。主 Agent 必须启动一个“专家教师子 Agent”来审视这份初稿。
**审查维度**：
1. **知识点归纳准度**：是否把表面考法误当成了底层逻辑？
2. **易错点针对性**：易错点是否是真正的学生痛点，还是不痛不痒的废话？
3. **变式梯度合理性**：挑选的 3-5 道拓展题，是否真正做到了“由浅入深”？有没有偏题、怪题或超纲题？
**处理动作**：若子 Agent 认为存在问题，必须出具修改意见，主 Agent 据此对初稿进行回炉重造，直到子 Agent 给出“通过”评级。

### Step 5：💾 产物落地与格式自检子 Agent (Formatting QA)
将通过审查的文档保存至本地目录（例如：`handouts/题目解析_知识点名称.md`）。
文件落地后，**强制启动“格式审查子 Agent”**执行最后一道防线：
1. **主动回读**：使用 `read_file` 工具读取刚生成的 `.md` 文件内容。
2. **LaTeX 扫描**：重点检查是否存在缺失的 `$` 或 `$$`、数学环境外裸露的下划线 `_` 导致的渲染失败、公式内部换行错误等。
3. **极简排版扫描**：检查标题和题号旁是否偷偷混入了括号修饰词（如 `（基础）`、`（来源于XX）`）。
若发现任何排版或渲染问题，自动使用 `string_replace` 等编辑工具修正，再次回读，直至 100% 纯净无乱码。

### Step 6：🚀 交付与自我迭代
确认文档无误后，向用户交付结果，并在本 SKILL 的【历次迭代经验库】中记录本次解构了什么神仙题型，搜题过程遇到了什么阻碍及解决方案。
