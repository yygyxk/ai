## 技能描述
本技能专为教培副业设计，用于将市面上的教辅资料（**完整 PDF 教辅**、PDF 切片、截图、纯文本）精准提取并转化为高颜值、标准化的 Markdown 讲义。**v2.0 核心升级**：支持上传完整版 PDF（如《五三》整本），自动提取目录、按关键词定位章节、切片提取文本与图片，彻底告别低效的人工截图流程。内置严密的 LaTeX 公式约束、排版骨架、**校验子 Agent** 和**自我迭代机制**，确保讲义随每次使用不断优化，达到可直接售卖或分发的商业级标准。

## 执行工作流 (Agent Workflow)

### Step 0：📦 PDF 自动化处理流水线（v2.0 新增，当输入为完整 PDF 时触发）

当用户上传**完整版 PDF 教辅**（如整本《五三》），并指定目标章节关键词时，执行以下自动化流水线：

#### Step 0.1：提取 PDF 目录
```bash
python3 scripts/pdf_chapter_extractor.py extract-toc <pdf_path>
```
- 使用 PyMuPDF 提取 PDF 书签/目录结构，输出为 JSON。
- 如果 PDF 没有书签，自动回退到全文搜索模式。

#### Step 0.2：按关键词定位章节
```bash
python3 scripts/pdf_chapter_extractor.py find-chapter <pdf_path> "<keyword>"
```
- 在目录中模糊搜索关键词（如"集合"匹配"1.1 集合"）。
- 自动推断章节的页码范围（起止页）。
- 如果目录中无匹配，回退到全文搜索，定位关键词出现的页码范围。

#### Step 0.3：提取章节内容（文本 + 图片）
```bash
python3 scripts/pdf_chapter_extractor.py full-pipeline <pdf_path> "<keyword>" <output_dir>
```
一键执行全流程，输出以下文件：
- `chapter_text.txt`：纯文本内容（PyMuPDF 提取）
- `chapter_text_layout.txt`：保留排版信息的文本（pdfplumber 提取，推荐）
- `images/`：章节内嵌入的图片
- `page_screenshots/`：整页高清截图（200 DPI，供视觉模型使用）
- `toc.json`：完整目录结构
- `extraction_summary.json`：提取摘要

#### Step 0.4：内容交付给后续步骤
提取完成后，Agent 按以下优先级使用内容：
1. **`page_screenshots/`（整页截图）**：发送给视觉模型，获取最准确的排版、公式和图表识别。**这是最可靠的方式**，因为 PDF 文本提取经常会丢失公式结构。
2. **`chapter_text_layout.txt`**：作为辅助文本参考，帮助理解页面结构。
3. **`images/`**：单独的嵌入图片，可附加到视觉模型输入中。

⚠️ **重要原则**：PDF 文本提取对数学公式极不可靠（分数、根号、上下标等都会丢失结构），**必须优先使用整页截图 + 视觉模型**进行内容识别。

### Step 1：资料解析与预处理
- **如果用户输入的是完整 PDF**：执行 Step 0 流水线，获取章节截图和文本，然后以截图为主、文本为辅进行内容识别。
- 如果用户输入的是图片，使用视觉模型能力识别其中的文字、公式和图形。
- 如果用户提供了具体章节名称或目标，请在生成时带上相应的标题。
- **读取本 Skill 底部的【历次迭代经验库】**，在生成前先回顾上一次积累的注意事项，不重蹈覆辙。

### Step 2：核心提取规则（系统指令）
在处理用户提供的资料时，**必须绝对遵守**以下指令：
1. **忠于原意（零幻觉）**：绝不能自己编造公式、定理或题目，必须 100% 基于用户提供的原始资料提取。
2. **极致排版（LaTeX 强制）**：所有数学符号、公式、方程式，**必须绝对严格使用 LaTeX 语法**。
3. **多源目录强制读取约束**：针对现阶段“复习巩固”定位的讲义，**题量与题型必须海量且极其全面**。
   - **知识点提取**：必须主动读取远程仓库 `math-materials/知识点` 文件夹下的教辅（如《教材帮》），做到知识点深挖到极细颗粒度。
   - **题型与题目提取**：必须主动读取远程仓库 `math-materials/资料` 文件夹（如《五三》、《必刷题》、《一遍过》等）以及 `math-materials/真题` 文件夹，**绝不容许任何核心题型的遗漏**。
4. **讲义颗粒度细化原则**：切忌将一个大章节（如“集合”）压缩进一份讲义。必须按知识体系拆分成多份极细颗粒度的讲义（例如拆分为《1.1.1 集合的概念与表示》、《1.1.2 集合间的关系与运算》）。每一份讲义都必须对标《教材帮》的深度，做到知识点极度全面。行内公式用单美元符号 `$` 包裹，独立居中公式用双美元符号 `$$` 包裹。不得使用 Unicode 字符代替复杂公式。
3. **北京高考考情分析（必加）**：每次生成必须结合远端教材仓库中的北京历年高考试卷（2008-2025），在讲义中设立独立模块，分析该知识点在历年北京高考中的【常考位置】、【平均分值】与【考查形式】，让学生带着高考目标学习。

### Step 3：标准化双版本 Markdown 输出
每次任务必须同时产出两个独立的内容：**【教师用书】**与**【学生讲义】**。

#### 核心模块定义：
## 一、 知识精讲与深度剖析
- **教师版**：全量提取核心定义、定理、推导过程，关键概念加粗高亮。要求**极度全面、细致**，绝不可遗漏任何推论、性质和次要考点（例如：含 $n$ 个元素的集合的子集个数公式 $2^n$ 等）。
- **学生版**：将定理中的**核心字词、关键公式挖空**。纯文本挖空替换为 `________`（填空线）。**【防雷警告】**：严禁在 LaTeX 公式 `$` 内部直接使用连续下划线 `___`（会引发 Missing open brace 渲染报错），若需在公式内挖空，必须使用 `\underline{\quad\quad}` 代替！

## 二、 必背符号与性质
- **教师版**：完整表格呈现。
- **学生版**：表格关键单元格留空。

## 三、 北京高考命题考情速递
- **教师版与学生版均保留**：明确指出该章节知识点在历年（2008-2025）北京高考数学卷中的**常考位置**（如选择题第1题、填空题等）、**平均分值**、以及**核心考查形式**（如结合不等式、定义新运算等），让学生一开始就建立高考全局观。

## 四、 核心题型与精选变式
> **核心铁律（多源融合扫荡）**：必须跨越 `math-materials/资料`（如53/必刷题等）和 `math-materials/真题` 文件夹进行地毯式搜索，【穷尽】所有核心题型，绝不能遗漏考法。
> **梯度铁律**：题型的编排与变式必须严格遵循【循序渐进，难度递增】的原则。从最基础的概念辨析，到中档的综合计算，再到高难度的高考压轴创新，层层递进。
> **海量题库支撑**：每个具体题型下配备：**1 道典例 + 3~4 道难度梯度的阶梯变式**（相较于之前的2道变式，要显著增加训练量），确保讲义内容达到复习课“高强度狂练”的充实度。

**【典例】**：[完整题目，含来源标注]
- **教师版**：保留【思路点拨】和完整的【规范解答】。
- **学生版**：隐藏【思路点拨】，隐藏【规范解答】，替换为：`<br><br><br><br><br> <!-- 作答留白 -->`。

**【变式训练】**：[完整题目]
- **教师版**：完整的详细解析。
- **学生版**：隐藏解析，留出作答空间。

## 五、 易错坑点防雷
- **教师版**：- 🧨 **易错点**：[描述] → **正确做法**：[说明]
- **学生版**：- 🧨 **思考**：[抛出易错场景的引导性提问，留出横线作答]

### Step 4：主 Agent 生成初稿
主 Agent 按 Step 3 骨架完成讲义 Markdown 的完整生成，产出**初稿（Draft v1）**，暂不直接输出给用户。

### Step 4.5：🕵️ 启动校验子 Agent（每次生成后必须执行）

主 Agent 完成初稿后，**立即以子 Agent 身份重新审视该初稿**，扮演一位"严苛的数学教研主编"，从以下三个维度对初稿进行独立校验，并输出结构化的**校验报告**：

#### 维度一：数学准确性校验（最高优先级）
- [ ] **公式验证**：逐一检查每个 LaTeX 公式语法是否正确（括号是否匹配、上下标是否正确、分数线是否完整）。
- [ ] **计算验证**：对所有"规范解答"中的计算步骤进行复算，确认结果无误。
- [ ] **零幻觉验证**：对比原始资料（用户输入的图片/文本），检查是否存在原书没有但讲义中出现的"自创"内容。若有，标记为 ⚠️ **幻觉风险**。

#### 维度二：排版与结构校验
- [ ] **骨架完整性**：四大模块（核心概念、必背符号、核心题型、易错坑点）是否全部存在且结构完整。
- [ ] **表格合规性**：表格的列对齐、`|` 符号是否规范，在 Markdown 渲染器中能否正常显示。
- [ ] **LaTeX 渲染风险**：行内公式 `$` 和独立公式 `$$` 是否混用正确，有无遗漏美元符号导致公式以纯文本显示的风险。

#### 维度三：教学质量与精简度校验
- [ ] **双版本验证**：是否输出了完全对应的教师版和学生版？学生版是否正确执行了挖空和解析隐藏？**重点排查**：学生版的 LaTeX 公式内是否存在连续下划线 `___` 导致的渲染风险？
- [ ] **题量克制**：检查每个题型下的练习题，是否严格控制在 1-2 道变式以内？（如发现题海式堆砌，立刻判定为 🔴 严重错误）。
- [ ] **衡中模式容量评估（当堂检测）**：独立评估【当堂过关检测】模块。题量是否达到了 7-8 道的极限容量？是否严格划分为 A/B/C 三个层级？结合题目的计算量评估：一个中等生在 10 分钟内是否会感到时间极度紧迫甚至做不完？如果只有 3-4 道简单题（太轻松），立刻判定为 🔴 严重错误，强制主 Agent 增加检测题量。
- [ ] **思路点拨质量**：【思路点拨】是否真正指出了破题的核心，而非只是重复题目条件。

#### 校验报告格式（子 Agent 必须按此格式输出）
```
## 📋 讲义校验报告

### 总体评级：[✅ 通过 / ⚠️ 需修订 / ❌ 重大错误需重生成]

### 问题清单：
| 问题编号 | 维度 | 位置 | 问题描述 | 严重程度 | 修复建议 |
|:---:|:---:|:---|:---|:---:|:---|
| #1 | 数学准确性 | 题型一·典例·规范解答 | 第3行公式括号未闭合 | 🔴 严重 | 补全右括号 |
| #2 | 排版结构 | 二、必背符号 | 性质表格第2列对齐异常 | 🟡 一般 | 检查 | 符号 |
| #3 | 教学质量 | 四、易错点 | 遗漏原书"互异性"相关警示 | 🟡 一般 | 补充该易错点 |

### 通过项：
- ✅ 所有独立公式均使用 `$$` 包裹
- ✅ 典例来源标注完整
- ✅ ...
```

#### 主 Agent 的决策规则
- 若报告中存在 🔴 **严重**问题 → 主 Agent **必须修订初稿**，修复所有严重问题后，产出 **Final 版**再交付用户。
- 若报告中只有 🟡 **一般**问题 → 主 Agent 判断是否修订，并在交付时将未修复的问题**附注给用户**，由用户决定。
- 若报告为**全部通过** → 直接交付初稿，同时附上"✅ 已通过三维度校验"的标注。

### Step 5：产物交付
将校验后的两个版本讲义分别严格保存为：
- `[章节号]_[章节名称]_教师版.md` （例如：`1.1_集合_教师版.md`）
- `[章节号]_[章节名称]_学生版.md` （例如：`1.1_集合_学生版.md`）
> **⚠️ 严格命名规范**：不仅**文件名**中严禁加入任何宣传修饰词，**讲义正文中所有的各级标题（包括#、##、###等）以及题目编号（如【典例1】、【变式1-1】）旁边，严禁加上任何括号标注来源、难度或宣传语。** 例如严禁出现“### 题型一：概念辨析（基础防雷）”或“**【变式 1-1】(《一遍过》基础)**”，必须写成极简且干净的“### 题型一：概念辨析”和“**【变式 1-1】**”。

### Step 5.5：🚨 Markdown 格式强制回读自检（防乱码机制）
在将文件生成并保存到本地后，Agent **必须主动使用文件读取工具**重新读取刚刚生成的 `.md` 文件内容，进行最终的安全扫描与审查：
1. 扫描是否存在 LaTeX 解析错误（特别是检查 `$` 内是否含有连续下划线 `___`）。
2. 检查 `$` 与 `$$` 是否规范且成对闭合。
3. 检查是否有因 Markdown 特殊字符冲突导致的乱码情况（如表格错乱）。
若回读审查发现任何排版或格式错误，必须立即修改文件并再次回读自检，直到确信文件 100% 能完美渲染后，方可完成任务并通知用户交付。

**自动生成 HTML 渲染版**
保存 `.md` 文件后，**自动对两个文件均执行** HTML 渲染：
```bash
python3 scripts/handout_renderer.py render-html <md_file_path>
```
- 在同一目录下生成同名 `.html` 文件，内嵌 KaTeX 渲染库。
- 用户可直接用浏览器打开 HTML 文件，确保所有数学公式完美渲染，**无需依赖任何 Markdown 编辑器**。
- 同时在经验库中记录本次生成的章节信息和任何新的经验。

### Step 6：🔄 自我迭代（每次使用后必须执行）
每次完成讲义生成后，**必须执行以下反思流程**，并将总结写回本文件底部的【历次迭代经验库】：

1. **质量复盘**：本次生成中，有哪些 LaTeX 公式写法或排版结构是特别好的？有哪些是生硬/不自然的？
2. **结构优化**：本次资料的结构（如《五三》的"考点清单+题型清单"双轨结构）是否与骨架完美匹配？有没有需要调整骨架的地方？
3. **经验沉淀**：将本次的改进点，**用"章节/题材"为 Key**，追加写入底部的【历次迭代经验库】中。
4. **更新版本号**：在文件顶部的"版本"和"迭代历史"字段中，更新本次迭代的内容说明。
5. **同步备份**：将更新后的 Skill 同步写入 `~/Downloads/个人/math-handout-generator-SKILL.md`，保持两份文件一致。

### 📌 [2026-05-20] 集合（高一数学·《五三》A版 1.1）

**资料特点**：
《五三》的排版是"考点清单 + 题型清单"双轨结构，非单一知识树。提取时需识别这两个不同的栏目并分别归入骨架的"核心概念速记"和"核心题型与母题"两部分。

**有效做法**：
- 原书的"集合间基本关系"部分用了表格（关系/文字语言/记法三列），直接在 Markdown 中用 `|` 表格还原，排版效果极佳。
- 并集/交集/补集的性质用三列对照表呈现，视觉对比清晰，**强烈建议后续章节中凡有"三元对比"的性质都用表格**。
